SpringBoot AOP切面编程：从概念到实战

引言：为什么需要AOP?

  • 我们平时写代码时痛点可能有：日志记录、权限校验功能，这会往往穿插在业务逻辑当中，导致代码冗余，耦合度高问题。
  • 如果每个接口都要加日志打印，难道要在每个方法中都写log.info或sout吗？显然不合理。
  • 所以，AOP就是为了解决这类问题而存在的。AOP能够让我们专注于业务，统一处理通用功能。

AOP核心概念

一起来做个假设：现在要给一个系统的接口加“日志记录”和“权限校验”：

  • 切面（Aspect）：
    可以理解为一个 “功能模块”，比如 日志切面里的打印日志逻辑，权限切面里的校验逻辑。相当于 通用功能的集合（各个功能模块）。

  • 连接点（Join Point）：
    系统中 “可以插入切面逻辑” 的点，可以理解为电影院里“可能被拦截检查”的所有时机或位置：走到检票口时，电影散场离开时。在 Spring 里，最常见的是 “方法执行时”（比如方法调用前、调用后），因为 Spring AOP 主要关注方法级别的拦截。

  • 切入点（Pointcut）：
    从所有连接点中 “筛选出需要应用切面的点”。可以理解为电影院规定 “只在观众进入放映厅门口时检票”，那么 “进入放映厅门口” 就是切入点。比如 “所有 Controller 中的方法” 就是一个切入点，我们只在这些方法上应用日志切面。

    [!NOTE]

    可理解为：连接点是 “所有可能的位置”，切入点是 “实际选择的位置”

  • 通知（Advice）：

    切面在切入点处 “具体要执行的逻辑”，比如日志切面在方法执行前打印 “开始调用”，在方法执行后打印 “调用结束”。

    Spring 中通知的类型有 5 种：

    • @Before：在目标方法执行前执行
    • @After：在目标方法执行后执行（无论是否抛出异常）
    • @AfterReturning：在目标方法正常返回后执行
    • @AfterThrowing：在目标方法抛出异常后执行
    • @Around：环绕目标方法执行（可以在方法执行前后、甚至修改返回值）

  • 目标对象（Target）：
    被切面拦截的对象（即业务逻辑对象，比如 Controller、Service 实例）。

  • 代理对象（Proxy）：
    Spring AOP 通过动态代理为目标对象创建的代理对象，切面逻辑会通过代理对象织入目标方法。在Spring中会自动帮你生成代理对象，不用手写。所以当你从 Spring 容器中获取目标对象（比如通过@Autowired注入）时，拿到的其实是 Spring 生成的代理对象，而不是原始的目标对象。

    因为代理对象和原始对象对外暴露的接口 / 方法是一致的（要么实现同一个接口，要么是子类），所以你用起来和直接操作原始对象完全一样，不需要修改调用方式。这种 “透明性” 正是 Spring AOP 的设计亮点 —— 让你专注于业务逻辑和切面逻辑，无需关心底层代理的实现。

  • 织入（Weaving）：
    将切面逻辑 “嵌入” 到目标对象的过程（Spring 在运行时通过动态代理自动完成织入）。

切入点表达式说明：

execution(* com.ruoyi.okz.service.impl.OkzOrderServiceImpl.consume(..)) 表示：

  • *：任意返回值类型

  • com.ruoyi.okz.service.impl.OkzOrderServiceImpl：目标类全路径

  • consume：目标方法名

  • (..)：任意参数列表

用 @Pointcut 注解定义切入点，语法是 AspectJ 表达式（重点讲常用语法）。

常用的 AspectJ 表达式示例：

  • execution(* com.example.demo.controller.*.*(..))：匹配 com.example.demo.controller 包下所有类的所有方法（* 表示任意返回值、任意类、任意方法，(..) 表示任意参数）。
  • @annotation(com.example.demo.annotation.Log)：匹配所有被 @Log 注解标记的方法。

AOP 在实际开发中的应用场景

除了上述 “流量日志记录”，AOP 还适用于以下场景：

  1. 日志记录：统一记录接口调用日志（入参、出参、耗时），无需侵入业务代码。

  2. 性能监控：通过@Around通知统计方法执行时间，识别慢接口。

  3. 权限校验：在方法执行前（@Before）检查用户权限，无权限则抛出异常。

  4. 事务管理：Spring 的@Transactional底层通过 AOP 实现事务的开启、提交、回滚。

  5. 异常处理：通过@AfterThrowing统一捕获异常并记录，如转换为友好提示。

  6. 缓存控制：在方法执行前检查缓存，存在则直接返回，否则执行方法并缓存结果。
