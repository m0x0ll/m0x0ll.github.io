JWT 与 Spring Security 问题与解答

一、基础概念与核心区别

1. 什么是 JWT？它的作用是什么？

  • 定义：JWT（JSON Web Token）是一种轻量级的令牌格式，以 JSON 为载体，用于在客户端与服务器之间安全传递身份信息。

  • 核心作用：

  • 存储用户身份数据（如userId、username、过期时间等）。

  • 通过签名机制（如 HS256）防止令牌被篡改，确保信息真实性。

  • 代码体现：在项目中由OkzTokenService（前台）和TokenService（后台）负责生成、解析，例如getFrontLoginUser(request)方法从请求头中提取并解析 JWT。

2. 什么是 Spring Security？它的核心功能是什么？

  • 定义：Spring Security 是基于 Spring 的安全框架，专注于身份认证（“你是谁”）和授权（“你能做什么”）。

  • 核心功能：

  • 身份认证：验证用户是否合法（如登录校验）。

  • 授权管理：控制用户对接口 / 资源的访问权限（如 “未登录用户不能访问订单详情”）。

  • 会话管理：处理用户登录状态（如基于 Token 的无状态会话）。

  • 代码体现：通过FrontSecurityConfig（前台）和SecurityConfig（后台）配置规则，例如antMatchers(“/onon/**”).permitAll()定义路径访问权限。

3. JWT 和 Spring Security 的区别是什么？

维度 JWT Spring Security
本质 令牌格式（数据载体） 安全框架（逻辑处理器）
核心职责 安全传递身份信息（防篡改） 验证身份 + 控制权限 + 管理会话
协作关系 作为 “身份凭证” 被 Spring Security 使用 依赖 JWT 解析结果执行后续安全逻辑

二、过滤器（Filter）的作用与执行逻辑

1. 为什么需要FrontJwtAuthenticationTokenFilter和JwtAuthenticationTokenFilter？

  • 核心作用：二者均为 “JWT 与 Spring Security 的桥梁”，负责将 JWT 令牌转换为 Spring Security 可识别的认证信息。

  • 具体逻辑：

  1. 从请求中提取 JWT 令牌（如Authorization头中的Bearer token）。

  2. 解析令牌获取用户信息（如FrontLoginUser或LoginUser）。

  3. 将用户信息封装为UsernamePasswordAuthenticationToken（Spring Security 标准认证对象）。

  4. 存入SecurityContextHolder（上下文容器），供后续权限校验使用。

2. 前台过滤器和后台过滤器的执行顺序是怎样的？

  • 优先级由@Order****决定：

  • 前台配置FrontSecurityConfig标注@Order(1)（优先级高）。

  • 后台配置SecurityConfig标注@Order(2)（优先级低）。

  • 执行流程（以/onon/order/detail请求为例）：

  1. 先进入前台过滤器：FrontJwtAuthenticationTokenFilter解析前台 JWT，设置认证信息。

  2. 再进入后台过滤器：JwtAuthenticationTokenFilter（因无antMatcher限制，默认处理所有请求）。

3. 为什么前台请求（/onon/**）会触发后台过滤器？

三、配置类（SecurityConfig）的逻辑与优先级

1. FrontSecurityConfig和SecurityConfig的作用分别是什么？

  • 前台配置（FrontSecurityConfig）：

  • 仅处理/onon/路径（通过antMatcher(“/onon/“)限制）。

  • 定义前台接口权限规则（如/onon/user/login允许匿名访问，其他需认证）。

  • 配置前台过滤器FrontJwtAuthenticationTokenFilter。

  • 后台配置（SecurityConfig）：

  • 处理所有路径（无antMatcher限制）。

  • 定义后台接口权限规则（如/admin/**需要认证）。

  • 配置后台过滤器JwtAuthenticationTokenFilter。

2. permitAll()的作用是什么？它会阻止过滤器执行吗？

  • 作用：permitAll()表示 “允许匿名访问该路径”，即无需认证即可通过权限校验。

  • 注意：permitAll()不会阻止过滤器执行，过滤器仍会解析请求（如打印日志），但后续权限校验会直接放行。

  • 示例：antMatchers(“/onon/**”).permitAll()表示前台路径无需后台认证，但后台过滤器仍可能被触发（需手动跳过）。

3. 为什么FrontSecurityConfig会优先处理/onon/**请求？

  • *原因 1：***@Order(1)**优先级更高：Spring Security 会先加载优先级高的配置。

  • **原因 2：***antMatcher(“/onon/*“)**精准匹配：前台配置明确指定只处理/onon/**路径，后台配置因优先级低且无路径限制，会 “让渡” 给前台配置先处理。

  • 效果：/onon/**请求先经过前台过滤器和权限校验，再进入后台配置流程。

四、整体请求流程总结（以/onon/order/detail为例）

  1. 请求到达：客户端发起/onon/order/detail请求，携带前台 JWT 令牌。

  2. 前台配置处理：

  • 因@Order(1)和antMatcher(“/onon/**”)，优先进入FrontSecurityConfig。

  • 执行FrontJwtAuthenticationTokenFilter：解析 JWT，设置FrontLoginUser到SecurityContextHolder。

  • 权限校验：anyRequest().authenticated()（因已设置认证信息，通过）。

  1. 后台配置处理：

  • 进入SecurityConfig（优先级低），执行JwtAuthenticationTokenFilter。

  • 若后台过滤器未跳过前台路径，会打印日志但因loginUser为null（无后台 JWT），不设置认证信息。

  • 权限校验：antMatchers(“/onon/**”).permitAll()（直接放行）。

  1. 接口执行：请求到达/onon/order/detail接口，执行业务逻辑。

五、关键类比与协作关系

组件 / 概念 类比场景 作用描述
JWT 登机牌 存储用户身份信息（如userId），通过签名防止伪造。
前台 / 后台过滤器 登机牌检查员 解析 JWT（核对登机牌），将用户信息转换为 Spring Security 可识别的 “已验证标签”。
Spring Security 配置类 安检规则与入口 规定 “哪些接口需要验证”（如登机口必须查登机牌），并检查 “已验证标签”。
@Order与antMatcher 门禁优先级 确保前台路径由前台配置优先处理，后台路径由后台配置处理，分工明确。

通过以上整理，可清晰理解 JWT、过滤器、Spring Security 的核心逻辑、协作关系及配置优先级对请求流程的影响。
